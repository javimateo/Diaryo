# Releasing

New versions are built by GitHub Actions and delivered to the installed apps by the
Tauri updater. The website links the latest installer.

## Version numbers

[Semantic versioning](https://semver.org): `MAJOR.MINOR.PATCH`. While diaryo is in beta
the major stays at 0: a new feature bumps the minor (0.3.0), a fix the patch (0.2.1).
1.0.0 will be the first stable version.

The version lives in three files, which must match:

- `package.json` → `"version"`
- `src-tauri/Cargo.toml` → `version` (`Cargo.lock` follows when building)
- `src-tauri/tauri.conf.json` → `"version"` (the one the updater compares)

## Publishing a version

1. From `develop`, create `release/X.Y.Z`, update the version in the three files and
   commit. Merge it into `main` (and back into `develop`) and push both.
2. Tag the merge commit on `main` and push the tag:

   ```bash
   git tag v0.2.1
   git push origin v0.2.1
   ```

3. The **Release** workflow (`.github/workflows/release.yml`) builds the Windows
   installer, signs it for the updater and leaves a **draft release** with:
   - `diaryo_X.Y.Z_x64-setup.exe` and its `.sig` signature;
   - `latest.json`, the file the installed apps read;
   - notes generated by GitHub from the commits since the previous version.
4. Review the draft on GitHub (Releases) and **publish** it. From then on, the installed
   apps find it.
5. Redeploy the website in Coolify so it shows the new version and size.

If the workflow fails after the tag was pushed, fix it, then move the tag to the new
commit:

```bash
git tag -d v0.2.1
git push origin :refs/tags/v0.2.1
git tag v0.2.1
git push origin v0.2.1
```

## Automatic updates

The desktop app (`src/desktop/updates.ts`) checks
`https://github.com/javimateo/Diaryo/releases/latest/download/latest.json` twenty
seconds after starting and every six hours.

- **Update automatically** on (the default, in Settings → Desktop): the new version
  downloads in the background and installs the next time the diary is hidden. The
  pending changes and a backup are saved first; the installer shows a small progress bar
  and reopens diaryo.
- Off: a notice offers to update now.

Updates are signed: the app only installs files signed with the project's private key.

- The **public** key is in `src-tauri/tauri.conf.json` (`plugins.updater.pubkey`).
- The **private** key is kept by the maintainer (`~/.tauri/diaryo.key`) and, for the
  workflow, in the repository secret `TAURI_SIGNING_PRIVATE_KEY` (plus
  `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` if it had one).

> **Never lose the private key.** Without it no new version can reach the apps already
> installed: users would have to reinstall by hand.

## The Windows warning

The installer is not code-signed yet, so Windows SmartScreen warns the first time it is
run ("More info" → "Run anyway"); the website explains this. Updates don't show it.
Signing the installer (for example with a free open-source signing program or Azure
Trusted Signing) would remove it.
